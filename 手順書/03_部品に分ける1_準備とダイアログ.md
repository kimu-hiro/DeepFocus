## 1. 部品（コンポーネント）ってなに？

実はもう1つ使っている。`Practice.jsx` がそれ。

```jsx
//Practice.jsx
function Practice() {
  ...
  return <p>{RING_CIRCUMFERENCE}</p>;
}
export default Practice
```

```jsx
//App.jsx
import Practice from './Practice.jsx'
...
<Practice />
```

| 書いたもの | 意味 | 例え |
|---|---|---|
| `function Practice() { return (...) }` | 画面の一部を作る関数 | 部品を作る工場 |
| `export default Practice` | ほかのファイルから使えるようにする | 部品を出荷する |
| `import Practice from '...'` | ほかのファイルの部品を持ってくる | 部品を取り寄せる |
| `<Practice />` | 部品を画面に置く | 部品をはめ込む |

部品の名前は**大文字で始める**。小文字だと HTML のタグ（`div` など）と勘違いされる。

## 2. props ってなに？（部品に渡す材料）

`Practice` は何ももらわずに動く。でも、ほとんどの部品は**親（App）から何かをもらって**動く。
その「もらう物」を **props**（プロップス）と呼ぶ。

```
App（親）
│
│ mode="work" を渡す
▼
ConfirmDialog（子）
  props.mode で受け取る
```

書き方は、HTML の属性（`className="..."` など）と同じ形。

```jsx
//渡す側（App）
<ConfirmDialog mode={mode} />

//受け取る側（ConfirmDialog）
function ConfirmDialog(props) {
  props.mode  // ← "work" か "break" が入っている
}
```

例え：**部品への手紙**。親が `mode` という名前で書いた手紙を、子は `props` という封筒から取り出して読む。

`props.` が付いていれば、「これは親からもらった物だ」と一目で分かる。

### 関数も渡せる（電話番号を渡す）

ダイアログの「記録する」ボタンを押したときの処理（`saveAndRun`）は、App が持っている。
子は、その処理を**関数ごと**受け取って、ボタンに付ける。

```jsx
//渡す側（App）
<ConfirmDialog onSave={saveAndRun} />

//受け取る側（ConfirmDialog）
<button onClick={props.onSave}>記録する</button>
```

```
ボタンが押された
   │
   ▼
ConfirmDialog「押されたよ！」
   │ props.onSave に電話
   ▼
App の saveAndRun が動く
```

例え：親が子に**電話番号**を渡しておく。子は「押されたよ」と電話するだけ。何をするかは親が決める。

| 名前の付け方 | 意味 | 例 |
|---|---|---|
| `on〇〇` | 「〇〇が起きたら呼んでね」という関数 | `onSave`、`onCancel` |
| それ以外 | ただの値 | `mode`、`records` |

### なぜ `onSave={saveAndRun}` と名前を変えるの？

同じ名前にしてもエラーにはならない（`mode={mode}` は同じ名前で渡している）。
名前を変えるのは、**見ている立場が違う**から。

| 立場 | 知っていること | 名前 |
|---|---|---|
| ConfirmDialog（子） | 「記録するボタンが押された」 | `onSave` |
| App（親） | 「保存して、リセットか切り替えをする」 | `saveAndRun` |

子は、押された後に親が何をするのかを知らない。知っているのは「ボタンが押された」ことだけ。
だから子の側の名前は、**起きたこと**で付ける。

例え：**店員の呼び出しボタン**。

```
店員（子）の目線
  「お客さんが呼び出しボタンを押した」
  → onCall（呼ばれた）

店長（親）の目線
  「レジを開けて、袋を用意する」
  → openRegisterAndPrepareBag
```

店員のボタンに「レジを開けて袋を用意する」と書いておくと、店長が仕事の中身を変えたときに、**ボタンの名前が嘘になる**。

DeepFocus でも同じことが起こり得る。

```
今：  onSave={saveAndRun}
  ↓ App の中身を変えたくなった
後：  onSave={saveAndShowMessage}
      ↑ 子の onSave はそのままでいい
```

子の側も `saveAndRun` という名前にしていたら、App を直すたびに子の名前も直すことになる。

## 4. `ConfirmDialog.jsx` を作る

`src/components/ConfirmDialog.jsx` を作って、まず外側だけ書く。

```jsx
//「記録しますか？」のダイアログ。
//ボタンを押した後の処理はAppが持っているので、
//関数で受け取る
function ConfirmDialog(props) {
  const modeLabel =
    props.mode === "work" ? "集中" : "休憩";

  return (
    //ここに App.jsx から切り取った <div> を貼る
  );
}

export default ConfirmDialog
```

`modeLabel` は、今 `mode === "work" ? "集中" : "休憩"` が**3回**書いてあるのを、1回で済ませるための名前。

`label`（ラベル）は「表示用の名前」という意味。`mode` は `"work"` のようにプログラムが見分ける印で、`modeLabel` は `"集中"` のように人が読む文字。同じ物の、人向けの名前だと分かるようにしている。

### 4-1. App から切り取って貼る

`App.jsx` で `confirmAction && (` を探す（`Cmd + F`）。
その下の `<div className="fixed inset-0 ...">` から、対になる `</div>` までを**切り取って**、上の「ここに貼る」の場所に貼る。

```
confirmAction && (
  <div className="fixed inset-0 ...">  ← ここから
    <div className="bg-white ...">
      ...
    </div>
  </div>                               ← ここまで
)
```

### 4-2. 貼ったものを書き換える

| 今の書き方 | 書き換え後 |
|---|---|
| `{mode === "work" ? "集中" : "休憩"}`（3か所） | `{modeLabel}` |
| `onClick={saveAndRun}` | `onClick={props.onSave}` |
| `onClick={runWithoutSaving}` | `onClick={props.onSkip}` |
| `onClick={() => setConfirmAction(null)}` | `onClick={props.onCancel}` |

## 5. App で使う

### 5-1. 取り寄せる

`App.jsx` の一番上、`import Practice ...` の下に足す。

```jsx
import ConfirmDialog from './components/ConfirmDialog.jsx'
```

### 5-2. 切り取った場所に置く

切り取った後に残った `{ confirmAction && ( ) }` の部分（前後の `{` `}` も含めて）を、これに置き換える。

```jsx
{confirmAction && (
  <ConfirmDialog
    mode={mode}
    onSave={saveAndRun}
    onSkip={runWithoutSaving}
    onCancel={() => setConfirmAction(null)}
  />
)}
```

| 渡すもの | 中身 | 子での使い道 |
|---|---|---|
| `mode` | `"work"` か `"break"` | 「集中」か「休憩」かを決める |
| `onSave` | `saveAndRun` | 「記録する」ボタン |
| `onSkip` | `runWithoutSaving` | 「記録しない」ボタン |
| `onCancel` | ダイアログを閉じる関数 | 「戻る」ボタン |

`confirmAction &&` を App 側に残すのは、「出すか出さないか」を決めるのが親の仕事だから。子は「出たときの見た目」だけを担当する。

## 6. 確認

`npm run dev` を打って、ブラウザで開く。

| チェック | やること |
|---|---|
| ☐ | タイマーを数秒動かして、リセット（■）を押す → ダイアログが出る |
| ☐ | 「集中時間を記録する」→ ダッシュボードに記録が増える |
| ☐ | 「記録しない」→ リセットされ、記録は増えない |

## 7. つまずいたら

| 症状 | よくある原因 | 確かめ方 |
|---|---|---|
| 画面が真っ白 | `export default` を忘れた／`import` のパス違い | ブラウザの Console のエラーを見る |
| `ConfirmDialog is not defined` | `import` を書き忘れた | App の一番上を見る |
| ダイアログが出る時に真っ白。Console に `saveAndRun is not defined` | 4-2 の書き換えを忘れた。`saveAndRun` は App にしか無い | ConfirmDialog の `onClick` が `props.〇〇` になっているか |
| ボタンを押しても何も起きない | `props.` を付け忘れた／渡す名前と受け取る名前が違う | 表の「渡すもの」と `props.〇〇` の名前が同じか |
| `return (` の後ろでエラー | 貼った `<div>` の閉じタグが足りない | `<div>` と `</div>` の数を数える |
