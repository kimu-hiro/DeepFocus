# 05 部品に分ける③ タブ

上の4つのタブを `TabBar.jsx` に分ける。
部品と props の考え方は、03 の「1」「2」を見る。

**見た目と動きは1つも変えない。**

---

## 0. ゴールの絵

```
App（親）
│
│ mode・view（今どこにいるか）
│ onTimerTabClick（work/breakが押されたら呼ぶ）
│ onViewChange（dashBoard/practiceが押されたら呼ぶ）
▼
TabBar（子）
  ├ どのタブが選ばれているか決める
  └ 4つのタブを光らせて並べる
```

今回はもう1つ、**work と break のタブの中身をまとめる**。
今は、ほとんど同じ15行が2回書いてある。

| 手順 | やること |
|---|---|
| 1 | App に `handleTimerTabClick` を作る（2回書いてある処理を1つに） |
| 2 | `TabBar.jsx` を作る |
| 3 | App で使う |

## 1. work/break タブの処理を1つにまとめる

### 今のコードを見比べる

`App.jsx` の workTime ボタンと breakTime ボタンの `onClick` を並べると、違うのは**3か所だけ**。

| | workTime ボタン | breakTime ボタン |
|---|---|---|
| どのモード以外なら | `mode !== "work"` | `mode !== "break"` |
| 経過時間の計算 | `breakTime - remainingTime` | `workTime - remainingTime` |
| 切り替え先 | `"work"` | `"break"` |

「経過時間の計算」は、**今のモードの設定時間**から残り時間を引いている。
今のモードの設定時間は、もう `currentTotalTime` という名前で App にある（`//円形プログレスバー用の計算` の所）。

```
work タブを押したとき
  今は break → breakTime - remainingTime
            = currentTotalTime - remainingTime

break タブを押したとき
  今は work  → workTime - remainingTime
            = currentTotalTime - remainingTime
```

だから、違いは「切り替え先」だけになる。これを引数 `targetMode` で受け取れば、1つの関数で済む。

### 関数を作る

`App.jsx` で `const progressRatio =` を探して、その行の**下**に書く。中で使う `currentTotalTime` より後ろに置くと、上から読んだときに「これは何？」とならずに済む。

```jsx
//タブでwork/breakを切り替える。
//途中まで進んでいたら、記録するか確認を出す
const handleTimerTabClick = (targetMode) => {
  setView("timer");
  if (mode === targetMode) return;
  const elapsed = currentTotalTime - remainingTime;
  if (elapsed > 1) {
    setConfirmAction({
      type: "switchMode",
      targetMode: targetMode,
    });
    return;
  }
  setMode(targetMode);
  setIsRunning(false);
  pausedTimeRef.current = null;
};
```

| 部分 | 何をしているか |
|---|---|
| `setView("timer")` | タイマー画面に戻る（今までは最後に書いていた。先に書いても結果は同じ） |
| `if (mode === targetMode) return;` | もうそのモードなら、何もせずに終わる |
| `elapsed > 1` なら確認を出して `return` | 途中まで進んでいたら、ダイアログに任せて終わる |
| 最後の3行 | ほとんど進んでいなければ、そのまま切り替える |

今までは `if` の中に `if` が入っていた（入れ子）。**だめな方を先に `return`** すると、入れ子がなくなって上から下へ読める。

```
今まで：              これから：
if (違うモード) {     if (同じモード) return
  if (少し) {         if (進んだ) { 確認; return }
    切り替え          切り替え
  } else {
    確認
  }
}
```

## 2. `TabBar.jsx` を作る

`src/components/TabBar.jsx` を作る。

```jsx
//ここに App から切り取った
//「4つの定数」と「getNeonTabClassName」を貼る（2-1）

//上の4つのタブ。
//押した後の処理はAppが持っているので、関数で受け取る
function TabBar(props) {
  //workとbreakはタイマー画面にいるときだけ選ばれている扱い
  const isWorkTabSelected =
    props.mode === "work" && props.view === "timer";
  const isBreakTabSelected =
    props.mode === "break" && props.view === "timer";
  const isDashboardTabSelected = props.view === "dashBoard";
  const isPracticeTabSelected = props.view === "practice";

  return (
    <nav className="flex border-b border-neutral-800">
      <button
        onClick={() => props.onTimerTabClick("work")}
        className={getNeonTabClassName(
          isWorkTabSelected, WORK_TAB_NEON
        )}
      >workTime</button>
      <button
        onClick={() => props.onTimerTabClick("break")}
        className={getNeonTabClassName(
          isBreakTabSelected, BREAK_TAB_NEON
        )}
      >breakTime</button>
      <button
        onClick={() => props.onViewChange("dashBoard")}
        className={getNeonTabClassName(
          isDashboardTabSelected, DASHBOARD_TAB_NEON
        )}
      >dashBoard</button>
      <button
        onClick={() => props.onViewChange("practice")}
        className={getNeonTabClassName(
          isPracticeTabSelected, PRACTICE_TAB_NEON
        )}
      >practice</button>
    </nav>
  );
}

export default TabBar
```

### 2-1. 定数と関数を切り取って貼る

`App.jsx` で `//ここからタブのための機能` を探す。
その下の **4つの定数（`WORK_TAB_NEON` など）** と **`getNeonTabClassName`** を切り取って、`TabBar.jsx` の「2-1」の場所に貼る。

`isWorkTabSelected` などの4行は、もう上のコードに書いてあるので、App からは**消すだけ**。

### なぜ定数と関数は `function TabBar` の外に置くの？

| 置き場所 | 中で使えるもの | 例え |
|---|---|---|
| `function TabBar` の**外** | props・state は使えない | 道具棚。誰でも同じ道具を使う |
| `function TabBar` の**中** | props・state が使える | 作業台。その時その時の材料で作る |

ネオンの色や `getNeonTabClassName` は、props を使わない**いつも同じ道具**。外に置くと、画面が描き直されるたびに作り直さずに済む。
`isWorkTabSelected` は `props.mode` を使うので、中に置く。

### `onClick={() => props.onTimerTabClick("work")}` の `() =>` はなぜ要るの？

```
onClick={() => props.onTimerTabClick("work")}
  → 押されたら電話して ✅

onClick={props.onTimerTabClick("work")}
  → 今すぐ電話して ❌（画面を描いた瞬間に動く）
```

`"work"` のように何かを渡したいときは、`() =>` で包んで「押されたら呼ぶ」形にする。
03 の `onClick={props.onSave}` は、何も渡さないので包まなくてよかった。

## 3. App で使う

### 3-1. 取り寄せる

`App.jsx` の一番上に足す。

```jsx
import TabBar from './components/TabBar.jsx'
```

### 3-2. `<nav>` を置き換える

`App.jsx` の `<nav className=...>` から `</nav>` まで（上の `{/* navタグは... */}` のコメントも）を消して、これを置く。

```jsx
<TabBar
  mode={mode}
  view={view}
  onTimerTabClick={handleTimerTabClick}
  onViewChange={setView}
/>
```

| 渡すもの | 中身 | 子での使い道 |
|---|---|---|
| `mode` | `"work"` か `"break"` | どのタブを灰色にするか |
| `view` | 今の画面 | どのタブを灰色にするか |
| `onTimerTabClick` | `handleTimerTabClick` | workTime・breakTime タブ |
| `onViewChange` | `setView` | dashBoard・practice タブ |

`setView` はそのまま渡せる。dashBoard・practice タブは、画面を変えるだけで、確認ダイアログが要らないから。

最後に、`//ここからタブのための機能⬇` と `//ここまでタブのための機能⬆` のコメントも消す（中身がもう無いため）。

`npm run dev` を打って、ブラウザで開く。

| チェック | やること |

## 5. つまずいたら

| 症状 | よくある原因 | 確かめ方 |
|---|---|---|
| タブが光らない | 定数を貼り忘れた／`getNeonTabClassName` が `function TabBar` の後ろにある | 定数と関数が**上**にあるか |
| `Too many re-renders` と出て真っ白 | `onClick` の `() =>` を忘れた | 4つの `onClick` を見る |
| 進めてからタブを押してもダイアログが出ない | `elapsed > 1` の向きが逆 | `>`（大なり）になっているか |
